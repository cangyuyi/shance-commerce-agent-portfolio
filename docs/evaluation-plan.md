# 评测方案

## 数据边界

- 20 条自建脱敏/虚构案例。
- 覆盖常规、缺失、冲突、违规、品牌语气、格式和多轮漂移场景。
- 当前对比数字为预置离线演示数据，只证明评测设计，不代表真实模型性能。

## 版本

1. V0：单次 Prompt。
2. V1：结构化输入、输出 Schema 与拒答规则。
3. V2：检索、生成、事实检查、合规检查和人工确认。

## 指标

| 指标 | 权重 |
|---|---:|
| 事实准确性 | 25 |
| 卖点覆盖 | 20 |
| 合规与安全 | 20 |
| 品牌一致性 | 15 |
| 内容可用性 | 10 |
| 格式稳定性 | 5 |
| 工作流成功率 | 5 |

## 评分原则

- 事实准确、卖点覆盖和格式通过优先使用确定性规则。
- 品牌一致性和可用性使用明确量表的人评为主。
- LLM Judge 只能作为辅助，先与人工在至少 5 条案例上校准。
- 同一批样本、相同模型参数和相同重试次数才能做版本对比。

## 复跑要求

接入模型 API 后：

1. 保存模型名、日期、Prompt 版本和温度参数。
2. 保存全部原始输入输出。
3. 自动计算确定性指标。
4. 抽取至少 20% 样本人工复核。
5. 用真实结果覆盖 `data/benchmark.json`。
6. 保留失败样本，不只展示最佳结果。
