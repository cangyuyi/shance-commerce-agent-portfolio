# 电商内容评测 Skill

## 目标

使用统一数据、评分规则和版本条件，评测电商营销内容质量。不得把离线分数描述成 GMV、转化率或其他线上业务收益。

## 触发条件

当用户要求：

- 评测商品文案、营销素材或内容 Agent；
- 比较 Prompt、模型或工作流版本；
- 建立 Benchmark、金标准或 Bad Case；
- 检查事实幻觉、卖点遗漏、品牌跑调或违规表述。

## 输入

至少需要：

- 商品事实；
- 必须覆盖的卖点；
- 禁止表述或合规规则；
- 品牌语气；
- 待评测输出。

缺少商品事实时不得对“事实准确性”给出通过结论，应标记 `insufficient_evidence`。

## 工作流

1. 按 `references/output-schema.md` 校验输入和输出。
2. 按 `references/evaluation-rubric.md` 逐项评分。
3. 确定性指标优先使用规则计算。
4. 主观指标使用人工评分；模型评分只能作为辅助。
5. 按 `references/bad-case-taxonomy.md` 归类错误。
6. 输出得分、证据、Bad Case、根因和建议。
7. 多版本比较时必须使用同一数据集和运行条件。

## 输出

- 版本信息；
- 分项得分与总分；
- 每项得分证据；
- Bad Case 列表；
- 根因分类；
- 推荐修改；
- 数据边界和限制。

## 安全与真实性

- 不补写不存在的商品事实。
- 不把模型自评当作唯一证据。
- 不隐藏失败样本。
- 不把离线评测结果包装成线上商业成果。
- 医疗、健康、安全和法律相关内容必须人工复核。

## 完成标准

- 所有数字可回查到样本或原始输出。
- 指标权重合计为 100。
- 多版本使用同一批数据。
- 已明确事实、假设、限制和待核验项。
